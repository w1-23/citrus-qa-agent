# 数据源覆盖边界与检索前自审

## 数据源覆盖边界（v8.17.17 修订：不再"仅联网"——一律本地+联网并发）
| 查询类型 | 覆盖来源 | 处理 |
|---|---|---|
| 学术论文 / 研究进展 / 机制 / 基因 / 代谢物 / 品种性状 | 本地文献库 + UCR 品种库 | `citrus_rag_search`（一次调用自动覆盖两类） |
| 品种 / 品种特性 / 品种来源 | 优先 UCR 品种库，文献补充 | 检索词使用品种学名、CRC/登记编号等精确角度 |
| 政府工作报告 / 政策文件 / 法规 | 本地库通常不覆盖，但**仍先并行发起本地检索**（可能命中相关综述/历史文献），同时发起联网 | 第 1 轮本地 `citrus_rag_search` + 联网 `deepseek_web_search` 并发；两路证据冲突时按仲裁规则消解 |
| 最新新闻 / 实时行情 / 近期事件 | 本地库通常不覆盖，但**仍先并行发起本地检索**，同时发起联网 | 同上——**不要做"仅联网"检索** |
| 非柑橘内容 | ❌ 不检索 | 直接说明不在检索范围 |

> 核心原则（v8.17.17，用户决策）：**涉及需要同时本地+联网的问题，一律并发发起两路检索**，最后汇总本地 [n] 与联网 [Wn] 做冲突消解；不得因"本地不覆盖"就跳过本地检索只做联网——本地库可能含背景综述/历史数据，两路并行成本相同、证据更全。

## 检索前自审（Supervisor 或 Retrieve-Agent 内部执行）
- 类型是否该来源覆盖？
- 联网状态：前端开关是否开启？（通过 `deepseek_web_search` 的返回判断；若无返回或 `[DISABLED]` 则不可用；联网仅第 1 轮 1 次）
- 历史证据是否已覆盖？
- 任一不满足就不发起检索，直接回答或如实声明边界。

## 检索后自审（依据检索回执）
- 回执中 `[检索统计] 通过 ≤2 条或过滤占比 ≥50%` → 该角度相关性低，不要继续刷检索。
- 回执含 ⚠ 联网不可用或无 `[Wn]` → 时效信息如实声明缺口，不要暗示曾联网。
- 收到 `[WEB_BUDGET_EXHAUSTED]` → 联网仅第 1 轮，已用尽，基于本地证据收尾。
