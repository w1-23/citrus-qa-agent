# 输出格式：事实查询

用于回答事实性问题。篇幅与结构由检索证据量决定，证据越丰富展开越充分；证据不足则如实收窄并声明缺口。

## 核心结论
用一段话直接回答，开头先 3-5 条要点（每条一句、结论先行、关键机制/数值挂 [n] 或 [Wn]）。

## 详细展开
- 维度数量与证据量匹配：
  - 去重文献 N ≥ 8 → 组织 4-6 个维度，每维度 2-4 段；
  - N = 3~7 → 2-3 个维度；
  - N ≤ 2 → 如实说明证据不足，不硬凑。
- 可选维度：分子机制 / 表型证据 / 生态或栽培意义 / 品种差异 / 病原互作 / 代谢通路 / 时间线演进 / 争议与分歧。
- 每段必须含证据中的具体内容（基因名、位点、数值、倍数、实验类型），并紧跟引用编号。
- 同一维度内出现 ≥3 个并列对象（品种×性状、处理×指标、年份×事件等）时优先改用表格，数值保留原文精度（倍数/±SD/p 值不得约写或省略到失真）；争议辨析、因果推理、限定语密集的维度保持段落文字，不压进表格。
- 引用编号使用检索回执中的 [n] / [Wn] 清单，不自行另编号。

## 证据说明
逐条列出：
- 依据：支撑本回答的关键证据编号与一句话要点。
- 缺口：证据不足的地方、未检索到的方向。
- 冲突：文献间冲突的结论（若有）。
- 区分“文献确证”与“模型推演”。

## 深入探索（仅在用户要求时输出）
给出 2-4 个可继续研究的方向或追问建议。默认不输出。
