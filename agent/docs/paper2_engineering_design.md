## 0. v5→v6 补钉的两处漏洞

### 漏洞1：CiteExist=1.0 的「空引用」悖论 → 补「引用覆盖率」
- 协议里 `cite_exist_score` 在"无引用"时返回 1.0，等价于"全对"。但"不引用"≠"引用无误"，而是"零问责"。
- 通用框架完全可能**一个 [n] 都不输出**（coverage=0），此时 CiteExist 虚高为 1.0，抹平了你的优势。
- **补第 4 个指标**：`引用覆盖率 CitationCoverage = #携带[n]的事实断言 / #所有事实断言`（claim 抽取时顺带标注，近乎零成本）。
- 由此护城河叙事变完整：**你的系统 = 覆盖率高 AND 存在性 1.0（全程问责且零幻觉）；基线 = 要么不引用（覆盖 0，无问责），要么编造引用（CiteExist<1）**。两个维度都压你输不了。

### 漏洞2：标注判例的「鸡生蛋」死锁 → 补 pilot 先行
- 协议要"判例从 84 题生成结果抽取"，但 κ 标注又需要判例先行——死锁。
- **补 pilot step**：先跑 **10 题 × 4 系统** 的小规模生成 → 从中抽 seed 判例（每档 2 正 1 反）→ 两名标注员校准 → 再全量跑 + 全量 κ。

## 1. 评测协议（终稿，可执行）

### 1.1 四指标定义（②①③ + 覆盖）

设注入证据 $E=\{e_1..e_m\}$，回答 $A$ 抽成事实断言 $C=\{c_1..c_k\}$。

| 指标 | 公式 | 分母 | 用途 | 标注 |
|---|---|---|---|---|
| **② 引用存在性** $\text{CiteExist}$ | $\frac{\#\{[n]\in A : n\le m\}}{\#\{[n]\in A\}}$ | 全部引用标记 | **护城河（排序）** | 全自动 |
| **① 证据支撑度** $\text{Support}$ | $\frac{\sum \text{score}(c_i)}{|C|}$，score∈{1,.5,0} | **所有事实断言** | 排序 | LLM-judge + κ |
| **③ 引用正确性** $\text{CiteCorrect}$ | $\frac{\#\{[n]: e_n \text{支撑}\}}{\#\{[n]: n\le m\}}$ | 存在的引用 | **仅诊断** | 与①合并 |
| **④ 引用覆盖率** $\text{CiteCover}$ | $\frac{\#\{c_i\text{ 带}[n]\}}{|C|}$ | 所有事实断言 | **排序（问责度）** | 全自动 |

**并列产出（对抗池）**：`诚实率 Honesty` = 诚实声明"未找到/不确定"的比例；`引用存在性幻觉率` = 1−CiteExist。

### 1.2 引用解析（四系统统一）
`[1] / [1][2] / [1,2] / [1-3] / [W1] / [H1]`；`[Wn][Hn]` 走独立验证（URL/账本），不进②；空回答/拒答 → ②=1 但计入诚实率分母；同一编号去重。

### 1.3 断言抽取 + 三档支撑
- 按句切分 → 提事实断言（数字/实体/因果/时间/比较）→ 排除观点/元叙述 → 每问 3-8 条
- 三档：完全=1.0（证据明确给出）/ 部分=0.5（涉及主题未给具体）/ 不支撑=0.0（无关或矛盾）

### 1.4 κ 校验流程（含 pilot 修正）
1. **pilot**：10 题 × 4 系统生成 → seed 判例（每档 2正1反）
2. 抽 200 条断言（池A 120 + 池B 80）→ 两名标注员独立标
3. quadratic-weighted Cohen's κ ≥ 0.80（不达标→校准→重标）
4. κ 达标后校准 LLM-judge（一致率 ≥85% 才启用）
5. LLM-judge 全量

### 1.5 公平基座 vs 编排自变量

| 层 | 统一（基座） | 自变量（编排差异） |
|---|---|---|
| embedding | e5-large ✅ | — |
| 语料/分块 | 同一 corpus ✅ | — |
| 生成器/prompt/temp | GC 协议，sha256 声明 ✅ | — |
| 证据编号 | 注入层 [1..m] ✅ | — |
| 稀疏通道 | — | Naive 无 / CitrusQA BM25+ |
| 精排 | — | Naive 无 / CitrusQA bge-reranker |
| 阈值 | — | Naive 固定top5 / CitrusQA 动态T |
| 引用过滤 | — | 基线无 / CitrusQA filter_refs |
| 早停 | — | Naive 无 / CitrusQA 代码级 |

**受控轨 = 主结论；开箱轨 = 附录。**

### 3.4 一个诚实的预期（提前说，别等审稿人抓）

- 受控轨里基线也用你的 e5-large 嵌入 + 同语料（否则归因不清），所以**基线未必烂到尘埃**——Naive 仍有"固定 top-5 无 rerank"的检索差，端到端会劣于你，但差距的**来源是编排不是嵌入**，这恰恰是你要的干净归因。
- **最大分化点一定在 R2（引用可信度），不在 R1（正确性）**：因为"正确性"各系统咬得紧（同一生成器+语料），而"有没有代码级过滤"是硬性鸿沟。论文重心应压在 R2。
