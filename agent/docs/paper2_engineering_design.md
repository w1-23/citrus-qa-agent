## 1. 表述边界（先收紧，防止被反例攻击）

- **指标②（引用存在性）**：代码级过滤保证每个 `[n]` 指向真实注入证据 → **存在性幻觉率 ≈ 0**。这是全自动、精确、你最强的卖点。
- **指标③（引用正确性）**：引用存在 ≠ 引用正确；模型可能"引用一条真实证据，但该证据不支撑那条断言"，这层过滤**管不到**，靠检索质量。
- **对外表述统一为**：`引用存在性幻觉率 (code-guaranteed citation existence)`，**禁止**笼统说"引用幻觉率=0"（会被指标③反例攻击）。

---

## 2. 引用三层指标：形式化定义（可直接进协议）

设系统对某题注入证据集合 $E=\{e_1,\dots,e_m\}$（编号 $1..m$），生成回答 $A$，$A$ 抽成事实断言集合 $C=\{c_1,\dots,c_k\}$。

| 指标 | 形式化 | 计算 | 标注需求 |
|---|---|---|---|
| **② 引用存在性** $\text{CiteExist}$ | $\dfrac{\#\{[n]\in\{1..m\}\}}{\#\{全部引用标记\}}$ | 全自动解析 | 无 |
| **① 证据支撑度** $\text{Support}$ | 断言 $c_i$ 被 $E$ 支撑的加权比例 | LLM-judge 全量 + 人工 κ 子集 | ~200 句 κ |
| **③ 引用正确性** $\text{CiteCorrect}$ | 在「存在的引用」中，真支撑对应断言的比例 | LLM-judge + 人工 κ 子集 | 与①合并 |

**Support 三档聚合（本次补钉，你上轮没写死）**：
- 完全支撑 = 1.0，部分支撑 = 0.5，不支撑 = 0.0
- 主指标 `Support = mean(权重)`，**同时报告** `full_support_rate`（完全支撑占比）作为辅助
- 否则"三档"无法变成可比标量，标注员对齐也没基准

**独立变量 → 指标映射（本次补钉）**：
- 指标① ← 独立变量是**检索管道**（证据质量）
- 指标② ← 独立变量是**引用过滤**（有无生成后验证）
- 指标③ ← 检索 + 过滤交互
- 三个指标各归因各的，不混在一个"综合分"里

## 3. 决策1：基线证据统一编号方案（✅ 可立即定稿）

**核心**：编号在「证据注入层」由评测 harness 统一施加，不交给各系统自己编。

```
注入格式（四系统字节级一致）：
Evidence [1]: <chunk_1>
Evidence [2]: <chunk_2>
...
Evidence [m]: <chunk_m>

生成器 system prompt（四系统一致，sha256 声明）：
"只依据以上 Evidence [1..m] 回答，引用时用 [n] 标注对应证据编号。"
```

- **CitrusQA**：编号来自确定性组装（passed chunks 有序），生成后**有一道代码级引用过滤**（验证每个 `[n] ∈ {1..m}`）。
- **基线（Naive/LangChain/LlamaIndex）**：harness 把各自 retriever 返回的 top-K 结果**编号后注入，不做任何过滤**，模型自由引用。

**由此**：唯一自变量 = 「生成后有无代码级引用过滤」，因变量 = `CiteExist`。
- CitrusQA：过滤保证 `CiteExist = 1.0`
- 基线：无过滤 → 模型可能输出 `[m+1]`、`[0]`、错号 → `CiteExist < 1.0`

**这才是可测、可归因的护城河**，不是"给基线装引用能力欺负人"——基线装了"引用能力"但没装"引用验证"，幻觉引用正是其真实缺陷。

## 4. 决策2：指标②自动解析规则（✅ 可立即定稿）

**覆盖引用标记形态**（复用第一篇解析器，扩展到基线）：
- `[1]` 单引用
- `[1][2]` 连续多引用
- `[1,2]` / `[1, 2]` 逗号列表
- `[1-3]` 范围（若出现）
- provenance 前缀：`[W1]` / `[H1]` / `[RAG]` / `[UCR]`（归一化到编号）

**判定流程（零标注）**：
1. 正则提取回答中全部引用标记
2. 归一化为编号集合（去掉前缀、展开范围/逗号）
3. `CiteExist = |提取编号 ∩ {1..m}| / |提取编号|`
4. **四系统用同一解析器**，判定标准一致（协议里写死：基线也用这套，不许各系统自定义解析）

## 5. 公平基线控制变量表（✅ 可立即定稿）

| 变量 | 轨1 受控 | 轨2 开箱 |
|---|---|---|
| 嵌入模型 | 统一 e5-large | 各用默认 |
| 语料分块 | 统一 | 统一（喂相同 chunk 文本） |
| 生成器 + system prompt | 锁死（sha256 声明） | 锁死 |
| 证据编号格式 | 统一 `[1..m]` | 统一 `[1..m]` |
| **检索后端逻辑** | **自变量** | 默认 |
| **生成后引用过滤** | **自变量（对指标②）** | 默认无 |
| temperature | 0 | 0 |

**归因铁律**：
- 轨1 比的是"管道编排 + 引用过滤"，不含模型/语料差异
- 轨2 比的是"开箱即用 vs 增强基线（加 rerank/改写）"，展示"即使调优也追不上"
- 两轨结果**分开报告**，不混进同一张表

| **40 的性质** | 是"时效性专项"，还是"**对抗样本**（语料库外 + 故意问细节，诱导模型编造引用）" |

**建议**：40 题中必须含**语料库外 + 追问细节**的对抗题，作为指标②的弹药；否则"引用存在性幻觉率"这个最强卖点会因天花板效应而测不出区分度。

## 7. 标注准则三档（判据框架，判例待评测集定）

| 档 | 判据 |
|---|---|
| **完全支撑** | 证据明确给出该断言的事实/数字/结论 |
| **部分支撑** | 证据涉及该主题但未给出断言具体内容（如断言"产量提升15%"，证据只说"产量提升"） |
| **不支撑** | 证据与断言无关或矛盾 |

**判例必须基于真实题目填充**（每条准则 2 正例 1 反例），否则标注员无法对齐、κ 算不出——故判例等评测集构成确定后再写。
