## 二、根因（证据链）

1. **物理内存过小**：本机仅 15.8 GB 物理内存（Win32_OperatingSystem
   TotalVisibleMemorySize），页面文件 C:\pagefile.sys 22.5 GB。
2. **历史内存耗尽记录（决定性证据）**：`Microsoft-Windows-Resource-
   Exhaustion-Detector` 事件日志：
   - 2026-08-20 20:42：python.exe(8240) 使用 **19.3 GB** 虚拟内存，
     python.exe(12104)/(11380) 各 **6.7 GB** —— 单轮实验多 python 进程
     虚拟内存合计 ~33 GB，远超物理内存。
   - 2026-08-18 11:24 / 11:22：同模式（17.9 GB + 5.4 GB）。
3. **昨晚时序吻合**：exp1b 重跑 → B3 时效 → exp1c 连续三个重型实验，
   每个都调用 `retriever = init_retriever()`：加载 LanceDB 8 表
   （252,681 chunks）+ multilingual-e5-large 嵌入模型 + bge-reranker-v2-m3
   重排模型 + BM25 索引 → 每进程虚拟内存 6~19 GB。三连跑 → 换页风暴 →
   整机假死。
4. **异常关机记录**：System 日志 id=6008/41——
   - 08-25 20:59 意外关闭
   - 08-26 09:28 意外关闭（均为"未先正常关机"重启）

## 三、判定

**主因 = 物理内存预算不足 + 重型检索实验连续叠加**。每个实验进程都要
把 LanceDB + 双模型 + BM25 全部载入内存（虚拟内存 6~19 GB/进程），
本机 15.8 GB 物理内存无法支撑连续三个此类进程，触发系统级换页，
表现为 GUI 假死。数据层面无损坏。

## 四、防复发措施（后续执行纪律）

1. **重型实验一律单进程串行**，实验之间检查 `FreePhysicalMemory`
   恢复至 ≥ 6 GB 再启动下一个（启动命令内加入内存护栏检查）。
2. **禁止自动并行两个 init_retriever() 进程**（同一时刻最多一个重型
   检索进程在跑）。
3. 重型脚本内显式 `gc.collect()` + 每个实验独立进程（跑完即退出释放）。
4. 论文类（docx 编辑 / 报告撰写）任务与重型实验错峰，避免 GUI 卡顿叠加、
   也避免用户使用电脑时整机假死。
5. 若需跑多实验：改用 `run_in_background` 单发 + 等待终态，不在一个
   窗口内连续高压。
