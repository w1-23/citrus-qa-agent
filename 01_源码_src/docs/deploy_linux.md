# CitrusQA Linux 部署

此部署方案先在现有 Linux/NVIDIA 主机上验证。网页服务、Agent、RAG 索引与模型运行在服务器；用户只需浏览器。每个账号有独立会话、输出目录和下载权限。管理员统一配置模型与联网 Key。

## 首次上线顺序

1. 管理员账号负责安装缺失的系统 Python 组件和配置系统服务；普通 Linux 账号 `wangziqiang` 运行应用。现有 Anaconda 为该账号所有，应用环境单独放在数据盘项目目录。
2. 项目统一部署在 `/home/WZQ/CitrusQA/`：`01_源码_src/` 是代码和网页、`02_配置_config/` 是配置、`agent/` 保存语料/模型缓存/状态/日志/用户文件、`.venv/` 是 Python 3.12 环境，`tmp/` 是临时空间。启动前确认 `/home` 挂载在数据盘。
3. 首期只绑定 `127.0.0.1:8000`，不直接对公网开放。启动后用 SSH 隧道访问：`ssh -N -L 8001:127.0.0.1:8000 -p 28022 wangziqiang@211.69.141.120`，再打开 `http://127.0.0.1:8001`。**第一个注册账号会成为管理员**，因此首次注册只通过此私有隧道完成。
4. 管理员登录后配置主模型和联网服务 Key；Key 保存在服务器 `agent/state/`，不进 GitHub。管理员面板可管理账号、每日限额、查看全局队列和请求审计记录。
5. 默认全局最多同时处理 10 个聊天请求，其他请求按 FIFO 排队；等待队列上限 100，单次最长等 15 分钟。审计保存问题、回答、工具名/状态摘要及附件元信息，保留 365 天；不保存附件原文或模型隐藏推理。记录不随用户删除会话而删除。
6. 购买域名后将 DNS 指向服务器，在 Nginx 或 Caddy 配置 HTTPS，并启用 `CITRUS_COOKIE_SECURE=1`。公网只开放 80/443；不要先开放应用端口或公网注册。

## 主机资源建议

现有机器有 96 核、128 GB 内存和两张 RTX PRO 6000D（每张显存单独为 84 GB）。首轮只给 RAG/推理进程使用一张卡，另一张卡保持空闲；用实际并发压测再决定是否拆分服务或启用第二张卡。代码、当前模型缓存和文献数据约 6.5 GiB，另预留索引增长、用户上传和备份空间。不要把 GPU 数量误当作共享显存。

当前不设置硬件级显存上限；活跃请求会共享同一个服务进程中的检索模型实例，不会每个请求加载一套模型，但 GPU 计算仍可能争用并存在显存溢出风险。先保持单 Uvicorn worker，避免重复加载模型；后续根据真实压力再设置显存隔离与更细粒度 GPU 调度。

## 进程与反向代理

普通账号创建了自己的 Anaconda，但其 `systemd --user` 登录常驻目前未启用。要让服务在 SSH 退出和机器重启后自动恢复，需要管理员创建 systemd 系统服务，设置 `User=wangziqiang`，启动命令指向 `/home/WZQ/CitrusQA/04_脚本_scripts/run_server.sh`，并配置 `Restart=on-failure`。Key 只通过管理员配置界面保存到受限目录；不要写进仓库、命令历史或服务日志。

Nginx/Caddy 反向代理应保留 SSE 流式响应（关闭该路径的代理缓冲并延长读取超时），限制上传请求体与请求速率，并将 Uvicorn 仅监听回环地址。HTTPS 配好后才开启安全 Cookie。不要在反向代理前公开初始管理员注册窗口；首个管理员创建完成后，关闭公网直连端口，只保留 HTTPS 入口。

## 多用户数据与维护

- 账号数据使用 SQLite，密码为 PBKDF2 哈希；无需收集邮箱。管理员能停用账号、重置临时密码和调整普通账号每日请求上限。默认上限为每人每天 30 轮，管理员不受该上限限制。
- 会话和生成文件按账号隔离；聊天内容和附件可能发送给管理员配置的模型及联网服务。上线前应在首页/隐私说明中告知用户，并用 HTTPS 保护传输。
- 附件只在当前会话处理，不加入共享语料。导出文件有期限清理；定期备份 `state/`、本地语料和模型配置，备份同样需要加密并限制管理员访问。
- 首期没有邮箱验证和自助找回密码；用户忘记密码时由管理员重置，并通过安全渠道交付一次性临时密码。
- 上线前验证两个普通账号互相访问对方会话、任务状态、引用、工作区文件和下载链接均被拒绝；确认普通账号无法访问管理设置。

## 仍需现场确认的信息

远程部署前需要服务器公网地址或 VPN 地址、Linux 发行版/版本、SSH 端口、服务运行用户名及已授权的 SSH 公钥登录方式。不要在聊天中发送服务器密码、私钥或模型 Key。域名购买后还需 DNS 记录和证书签发方式。完成这些信息确认后再连接服务器部署。
