## A. 消融实验与评测体系（2026-08 三轮讨论①，论文必需）

> 目标：一键跑批对比实验，不人工反复改代码。论文 A2 需要的四组实验都从这里出：检索质量对比 / 消融 / 证据策略对比 / 成本数据。

### A1. 消融开关体系【待做】

**现状**：`config.py` 是 pydantic-settings（优先级：环境变量 > config.yaml > 默认值），以下开关**已现成，改配置即消融**：

| 消融维度 | 开关 | 用法 |
|---|---|---|
| HyDE | `RAG_HYDE_ENABLED` | false = 无 HyDE |
| 静态前缀 | `CONTEXT_STATIC_PREFIX` | false = 回退旧行为 |
| 上下文预算 | `CONTEXT_BUDGET_ENABLED` | false = 不压缩 |
| 混合检索拆解 | `RRF_WEIGHT_BM25` / `RRF_WEIGHT_ORIG_DENSE` / `RRF_WEIGHT_HYDE_DENSE` | 权重设 0 模拟纯向量/纯 BM25 |
| 固定 vs 动态阈值 | `DYNAMIC_THRESHOLD_RATIO` / `RERANK_THRESHOLD` | ratio=0 → 纯固定 0.25 |
| 并行 vs 串行写作 | `PIPELINE_PARALLEL_SECTIONS` | 3 → 1 |
| 学术源 | `ACADEMIC_SOURCES` | 列表切换 |
| 沙箱/权限 | `SANDBOX_ENABLED` / `PERMISSION_MODE` | 安全消融 |

**需补的开关点**（每处 3~5 行代码，默认值 = 生产行为，不动现状；改完跑全量回归）：

| 消融维度 | 加在哪 | 做法 |
|---|---|---|
| 记忆开关（LTM 召回 / 常驻卡片 / 偏好注入，各自独立） | `context_manager.load` 装配处 | 加 `ABLATION_LTM` / `ABLATION_RESIDENT_CARDS` / `ABLATION_PREFERENCES` 三个 bool，默认 True；装配处 if 包裹 |
| 证据账本开关 | `context_manager.py` 约 399 行 `build_evidence_block` | 加 `ABLATION_EVIDENCE_LEDGER`，默认 True |
| 状态栏开关 | `expert_graph` 的 `<agent_status>` 注入点 | 加 `ABLATION_STATUS_BAR`，默认 True |
| **证据全文 vs 摘要回传**（核心消融） | `_build_full_retrieval_context` / 回执构建 | 加 `ABLATION_EVIDENCE_FULL`：True=全文（现状），False=只回传标题+DOI+摘要（模拟编码 Agent 式压缩） |
| 子代理禁用（变单 Agent ReAct） | supervisor 工具 schema 装配处（`supervisor_tools.py`） | 加 `ABLATION_SUBAGENTS`：False 时不注册 call_*_agent 工具，主管只能直调检索/写文件 |
| 重排开/关 | `multi_retriever` rerank 调用处 | 加 `ABLATION_RERANK`，默认 True |

**注意**：`settings` 是进程级单例，启动时读环境变量——跑批必须**每组配置一个子进程**（env 注入），不能在进程内热改。

### A2. 跑批脚本 run_ablation.py【待做】

**做法**（放 `agent/scripts/`，纯新增）：

```
scripts/
├── questions.jsonl        # 问题集
├── ablation_matrix.yaml   # 配置矩阵：一个 cell = 一组开关组合
└── run_ablation.py
    ├── 读矩阵 → 每 cell 起子进程（env 注入开关，同一份代码）
    ├── 逐题调用 /api/v2/chat（或直接调 graph），收集：回答全文、引用数、
    │   检索次数、token 用量、耗时、缓存命中、事件流
    ├── 落盘 results/<cell>/<qid>.jsonl + summary.csv
    ├── 断点续跑（已跑 cell 跳过）+ 失败重试 + 每题 token 预算上限
    └── 可选：LLM-as-a-Judge 批量评分 → 自动出对比表
```

**建议矩阵**（约 8 个 cell）：全开（基线）／关 HyDE／关重排／纯向量／纯 BM25／关证据账本／摘要回传／关子代理（单 Agent）／关记忆。每个 cell 跑同样问题集 → 配对对比。

### A3. 问题集收集【待做】

- **规模**：论文正式实验 100~120 题；内部验证 30~50 题即可跑通管线。
- **结构**（写入 questions.jsonl 的 schema）：`{id, category, question, followup?, gold_dois: [...], difficulty}`：
  - `mechanism` ×25（机制/深度类，触发子代理）
  - `compare` ×25（对比类）
  - `fact` ×25（数据查询类）
  - `followup` ×20（提问→追问对，测「证据账本免重检」——核心创新点必须单独测）
  - `review` ×8（综述写作类，成本高，少量）
- **来源**：从 `agent/state/sessions.db` 历史会话 + feedback 数据挖真实提问（现有约 180+ 会话是现成语料），按类挑，论文可写「来自真实用户」。
- **金标准**：每题配 2~5 个 DOI（`gold_dois`），用于自动判检索质量（引用正确率）；标注半天可完成；写作类用 LLM-as-Judge + 人工抽评 20%。
- **难度分层**：单证据可答 / 多证据综合 / 需检索-推理多轮，消融结果按难度分组统计（看「哪个开关在难题上收益最大」——论文最想要的图）。

### A4. 评估方法【待做】（对应旧待办 O2/O3，评估类此前暂缓，现论文需要，重启）

### B2. 开放全文获取【待做 · 高优先级】

**现状（先记下，后续修改）**：`academic_search` 只返回元数据 + 摘要（CrossRef 无全文，Semantic Scholar/PubMed 摘要字段）；本地 RAG 的 chunk 是全文片段，但联网学术检索拿不到正文——「证据全文」主线在联网路径是断的。

**做法**：
1. 新增 `fetch_open_access(doi)` 工具：按 DOI 依次查 **Unpaywall API**（`https://api.unpaywall.org/v2/{doi}?email=...`）→ 命中 `best_oa_location.url_for_pdf` → 下载 PDF → 复用现有 `pdf_read` 解析分块；
2. 备选源：**PMC OA**（`https://www.ncbi.nlm.nih.gov/pmc/utils/oa/oa.fcgi`，免费全文 XML，配 NCBI_ENTREZ_EMAIL 已有）、**bioRxiv**（`https://api.biorxiv.org/`）；
3. 接入点：a) 学术搜索命中后自动尝试抓全文进证据（有预算上限：每次请求 ≤2 篇、单篇 ≤30s）；b) 或做成显式工具由模型判断调用；
4. 权限边界：写缓存到 `.hf_cache/oa/`（按 DOI 缓存，防重复下载），不写工作区；走工具预算与熔断（INV-08）；
5. 论文价值：这是「证据全文」创新点的完整闭环，消融可加一维「有全文 vs 仅摘要」。

### B3. 网页读取工具【待做 · 高优先级】

**现状**：系统只能读本地文件，外部 URL 读不了。

**做法**：新增 `fetch_url(url)` 工具（读超时 15s、正文 ≤50KB、只读不写、domain 黑名单防 SSRF、结果入证据时同样带数据边界标记）。用途：导师给的品种网站直接问答；配合 B2 抓全文；后续网页资料入库的预处理。

### B4. 参考文献格式化导出【待做 · 中优先级】

**现状**：write_pipeline 已有 `_unify_references`（统一重编号、文末合并），但导出格式固定。

**做法**：包装为工具/参数 `export_references(format=gb7714|apa|bibtex)`，综述完成后按需导出规范引用；论文写作刚需 GB/T 7714。

### B5. 数据分析工具【暂缓（触发条件）】

- **现状**：`statistical_analysis` 仅 Pearson/Spearman 相关 + `experimental_design`，近期调用 0 次；
- **决策**：不删、不宣传；**触发条件**：确认有真实用户上传私有实验数据（CSV）做分析 → 再升级为通用分析（pandas + scipy：描述统计 / t 检验 / ANOVA / 回归）。

### B6. 绘图工具【暂缓（触发条件）】

- **决策**：现阶段不做（问答/综述是「读」场景，输出图表无落点；科研用户自己出图更可控）；
- **触发条件**：品种/产区对比问答上线后确有图表需求 → 做最小图表工具（柱状/折线，matplotlib，数据必须来自证据）。

### B7. 工具集演进方法论【进行中】

- **做法**：跑批脚本顺带输出**工具调用频次表**（谁被冷落一目了然）；每季度按频次数据决定加/删（书 §4.2.6 工具设计的演进）；论文可写「基于调用频次的工具集演进」。

## E. 实验与测试级事项（改代码必读）

1. **全量回归**：任何改动（含新增开关点）后 `python -m pytest tests -q` 必须 232 项全绿；本沙箱环境需 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`（anaconda base 的 anndata pytest 插件读 .env 报 extra_forbidden，与项目无关；rag-agent 环境无此问题）；
2. **新开关点配套测试**：每个消融开关加断言「默认值 = 生产行为」+「关闭后行为可观测」，并登记进 AGENT_CHANGES 的 INV→测试映射表（新开关不得破坏 INV-01/02/04/08）；
3. **真实服务复测清单**：AGENT_CHANGES §5 的七项（深度问题收敛、锁争抢降级、预算截断、心跳量级、状态栏、write 流水线、协议配对）每次大改后执行；
4. **消融实验的严谨性**：同题同配置配对对比；温度固定（main 0.2 / fast 0.0）；每题 token 预算上限；报告统计显著性（书 §6.7，配对检验）；
5. **成本台账**：跑批时记录每 cell 的总 token/费用/延迟，出成本对比表（论文 A2 实验④直接可用）。
