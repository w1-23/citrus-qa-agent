## 第 2 页｜为什么需要它：科研人的三座大山

- **页面内容**：三张卡片——① 文献太多读不完（示例语料 11.9 万条片段）② 搜索引擎只给链接不给答案 ③ 通用 AI 会「幻觉」——编造文献与数据；底部结论横幅「需要：只信真文献、每句可溯源、能自动成稿的助手」
- **视觉建议**：左中右三栏卡片（📚 / 🔗 / 🤖❌），底部结论条
- **讲稿**（约 240 字）：

> 先讲为什么做它。做科研有三座大山。
>
> 第一，**文献太多**。光柑橘一个领域，公开论文数以万计，我准备的示例语料就有近十二万条片段，人读不过来。
>
> 第二，**搜索引擎不够用**。学术搜索给的是链接不是答案，下载、阅读、总结仍要自己完成。
>
> 第三，也是最致命的：**通用 AI 会编造**。它答得头头是道，文献名、数据、结论可能是凭空生成的，这在科研里不可接受，业内称为「幻觉」。
>
> 所以目标很明确：做一个助手——**只基于真实文献回答，每句话可溯源，还能把几十篇文献组织成一篇综述**。

## 第 4 页｜原理总论：Agent = 大脑 + 眼睛 + 手脚

- **页面内容**：公式 `Agent = LLM + 上下文 + 工具`；三要素（大脑 LLM / 眼睛 上下文 / 手脚 工具）；ReAct 循环：思考 → 行动 → 观察；下方整体架构图
- **视觉建议**：上半页三圈 + 循环箭头；下半页架构图：用户 → Supervisor 主管 → 三个专员（检索 / 写作 / 分析），两侧挂「RAG 知识库」「记忆库」「工具包」；标注「书第 1 章」
- **讲稿**（约 280 字）：

> 这本书开篇给了一个公式，是全书的题眼：**Agent = LLM + 上下文 + 工具**。
>
> 把 Agent 想成一个员工：**LLM 是大脑**，负责思考与表达；**上下文是眼睛**——它能看见什么，取决于我们给它看了什么；**工具是手脚**——它能做什么，取决于给它配了什么设备。
>
> 三者之间转一个循环，书里叫 **ReAct**：先「想」该做什么，再「动」调用一个工具，然后「看」工具返回的结果，再想、再动……直到任务完成。
>
> 我的项目就是把这个循环工程化：谁当大脑、给它看什么、配什么工具、如何防止它空转。这张图是整体架构：用户提问进来，一个「主管」负责调度，下面三个「专员」——检索、写作、分析，旁边挂着知识库、记忆和工具包。接下来逐页拆解。

## 第 5 页｜提示词：给 AI 立人设、定规矩

- **页面内容**：书 §2.4 要点：系统提示词 = 人格 + 格式 + 组织方式 + 业务规则；我的做法：三份文件——`role.md`（角色与工作范围）、`constraints.md`（数据保真：不编造 DOI、冲突并列呈现、来源标注）、`decision_guide.md`（决策指南：路由表）
- **视觉建议**：左半书本章节要点；右半三张文件卡片；下方贴路由表小样：「保存现成内容 → write_local_file」「撰写新内容 → call_write_agent」「读文件 → read_local_file」
- **讲稿**（约 270 字）：

> 第一个零件：提示词，就是给 AI 的「**入职手册**」——告诉它你是谁、干什么、什么不能干。
>
> 书里说，好的系统提示词有四层：**人格、格式、组织方式、业务规则**。我拆成三份文件。
>
> 「角色」：你是柑橘科研助手，专精基因、代谢通路、病害、品种差异，工作范围写死，防止跑偏。
>
> 「约束」：科研底线——**不编造 DOI 与实验数据**；文献结论冲突就并列呈现、说明可能原因；每条信息必须标注来源：本地文献库、学术库、还是模型自身知识，标得清清楚楚。
>
> 「决策指南」：核心是一张**路由表**——「保存这段内容」走保存工具，「写一篇综述」走写作专员，「读这个文件」直接读。就像新员工拿到「这件事该找谁办」的流程表。
>
> 提示词决定 Agent 的下限：人设立不住、规矩定不严，后面所有工程都白搭。

## 第 6 页｜上下文工程（一）：静态前缀与 KV 缓存

- **页面内容**：书 §2.2 / §2.3：消息四种角色；KV Cache——相同前缀免重复计算；我的做法：**静态前缀**——系统提示词字节级稳定，命中 DeepSeek 上下文缓存；动态内容（格式指南、技能）追加到当前轮消息尾部，不动前缀；100 万 token 窗口；缓存命中率实时观测
- **视觉建议**：左边消息列表示意图（system/user/AI/tool 四行）；右边积木图：前几块带锁标记（静态前缀），后几块标「动态追加」；比喻「每次开会不用重读公司制度」
- **讲稿**（约 260 字）：

> 第二个零件：上下文管理。上下文是 AI 的「眼睛」——每次回答前，要把「它该知道的全部信息」打包发给它。这里有个工程问题：**贵**。
>
> 大模型有 KV 缓存机制：模型每次处理前都要读一遍已有材料，材料越长越贵；但如果**前半段每次都一模一样**，模型就能把它「背下来」，只处理新内容——又快又便宜。
>
> 所以第一招是「**静态前缀**」：系统提示词这些固定内容保证**字节级不变**地放在最前面，稳定命中缓存；变化的内容——本轮问题、格式指南、技能——全部**追加在后面**，绝不插到前面。这条简单的规矩，让每次请求省下可观的时间和费用。
>
> 同时设了**一百万 token 的上下文预算**，右上角圆环实时显示用量。

## 第 7 页｜上下文工程（二）：分级压缩与状态栏

- **页面内容**：书 §2.6 / §2.7：压缩策略（过长 → 贵、慢、注意力稀释）；分层压缩；Agent 状态栏；我的做法：软阈值 75% → 批量压缩至 50%；硬阈值 93% → 强制收尾；**保护名单**（最近 3 轮问答、被引用证据全文、DOI 编号不压）；checkpoint 增量摘要；`<agent_status>` 状态栏由代码注入（轮次 / 工具预算 / 去重文献数）
- **视觉建议**：左半工作台整理图（100% → 50%，三样东西打「保护」标记）；右半状态栏小黑条：`<agent_status> 轮次:2/4 · 已检索文献:6 · 预算剩余:68%`
- **讲稿**（约 280 字）：

> 上下文还会越长越乱：书桌堆满文件，找东西就慢；上下文过长，模型变慢变贵，还会「看花眼」。
>
> 我的设计是**分级压缩**：用到 75% 时自动批量整理，压到 50%；用到 93% 时强制收尾，不再开新任务。
>
> 但整理有讲究——**有些东西不能动**：最近三轮问答、被引用过的证据原文、DOI 编号等凭证，列入保护名单；只压旧的过程记录与低相关碎片。压缩是**增量**的：记住上次整理到哪一条，这次只处理新增部分，不会越压越糊。
>
> 另一个设计是「**Agent 状态栏**」：代码在每个关键节点把「第几轮、还能调几次工具、已检索几篇不重复文献」明确写成状态栏注入上下文——**不让模型自己从长历史里数**，因为实测它数着数着就数错。这相当于给员工挂一块实时更新的胸牌。

## 第 8 页｜记忆机制（一）：便利贴 + 长期笔记本

- **页面内容**：书 §3.1：记忆层次（工作记忆 / 短期 / 长期）；我的做法：**双层记忆**——① 常驻卡片（置信度 ≥0.8 的短事实，≤8 条、每条 ≤500 字，代码自动淘汰）② 长期事实库 LTM（ADD-only 只追加不改写，置信度 <0.5 拒绝写入，按「语义相似度 × 时间衰减」召回 top 5）；提取放后台，不与回答抢时间
- **视觉建议**：左半记忆金字塔；右半桌面便利贴图 + 索引卡抽屉（「只进不出」标签）
- **讲稿**（约 270 字）：

> 第三个零件：记忆。这是 Agent 与聊天机器人的分水岭——聊天机器人每句话都是「第一次见面」，Agent 应该记得你。
>
> 书里把记忆分层次：工作记忆、短期、长期。我的实现是**双层**：
>
> 第一层「**常驻卡片**」——显示器上贴的便利贴。只放高置信度的短事实，比如「用户偏好中文」「用户研究血橙花色苷」，最多 8 张、每张 ≤500 字，**每次对话自动带在眼前**；贴不下由代码按规则淘汰。
>
> 第二层「**长期事实库**」——工作日志。有价值的对话事实后台记录，遵循 **ADD-only**：只追加、不覆盖。同一件事说法变了，两版都保留，用时按「语义相似度 × 时间衰减」排出谁更可信。
>
> 细节：置信度低于 0.5 的事实**拒绝写入**——宁缺毋滥，防止把随口一句话当成你的永久设定。提取记忆在后台做，不拖慢回答。

## 第 9 页｜记忆机制（二）：偏好、域隔离与隐私

- **页面内容**：书 §3.1.8：隐私保护、日志脱敏；我的做法：**偏好两层**（全局跨会话 + 会话级覆盖）；**记忆域化**（会话记忆优先，置信 ≥0.9 才全局共享）；**PII 脱敏**（邮箱 / 手机 / 身份证 / 密钥自动打码）；API Key 只存本机 `state/api_key`（权限 600）
- **视觉建议**：左半「按会话分抽屉」图（会话 A / 全局 标签）；右半日志打码示例：`user email: j***@qq.com`
- **讲稿**（约 250 字）：

> 记忆还要讲规矩，我做了两件事。
>
> 第一是**分域**：这个会话里说的，属于「这个会话的笔记」；而「我写综述偏好中文」这种用户级偏好，提升为**全局偏好**，新会话也生效；会话里的具体细节不跨域乱串。改版之前偏好按会话存，用户在一个会话说「用中文」，换个会话它又写英文了——现在两层分开，稳定了。
>
> 第二是**隐私**：日志自动给邮箱、手机号、身份证号、密钥打码；API Key 只存在本地文件、权限 600（仅你的账户可读）；除调用模型接口外，**系统不向任何外部服务器发数据**。书里专节讲日志脱敏，我把它做成默认功能，而不是可选项。

## 第 10 页｜RAG 知识库（一）：把文献变成「语义图书馆」

- **页面内容**：书 §3.2.1 / §3.2.2：分块（Chunking）；稠密嵌入（从词汇关联到语义理解）；我的做法：示例语料 11.9 万条片段（5 批次公开柑橘文献）；`multilingual-e5-large` 多语言嵌入；LanceDB 嵌入式向量库（百万级、热更新、免部署）；`ingest.py` 一键导入自己的 PDF/txt/md
- **视觉建议**：左半「文档 → 切块 → 编号」三步；右半书架 + 语义索引卡；下方导入漏斗图
- **讲稿**（约 270 字）：

> 第四、五个零件：知识从哪来？模型自带的知识不够专业，所以系统外挂知识库，这套技术书里叫 **RAG——检索增强生成**。
>
> 第一步**分块**：文献不能整篇塞给模型——太长、太贵、答时抓不住重点。我把每篇切成几百字的片段，共**十一万九千条**，每条记住来源文献与位置。
>
> 第二步**向量化**：用嵌入模型把每段文字变成一串数字（向量），**意思相近则数字相近**。我用多语言嵌入模型，中英文文献都处理。这相当于图书管理员给每本书做「语义索引卡」——按意思排，不按字排。
>
> 存储用 **LanceDB** 嵌入式向量库：百万级、新文献导入立刻可搜、无需安装任何数据库服务。想导入自己的文献？PDF 丢进导入目录，一条命令自动分块入库。

## 第 11 页｜RAG 知识库（二）：两阶段检索与动态阈值

- **页面内容**：书 §3.2.3 / §3.2.4：稀疏嵌入（BM25 精确匹配）与稠密互补；混合检索；我的做法：**混合检索**（BM25 倒排索引 + 向量语义并行，融合打分）；**交叉编码重排**（bge-reranker-v2-m3 精排）；**HyDE**（先生成假设答案再检索）；**动态阈值**——`max(0.25 地板, 本轮最高分 × 0.6)`，分数分布写入检索日志，后续用统计分布更新地板（自适应筛选）
- **视觉建议**：左半招聘流程两栏：「简历海选（BM25+向量，粗筛）」「现场面试（重排模型，精排）」；右半阈值示意：分数直方图 + 0.25 底线 + 动态线
- **讲稿**（约 300 字）：

> 检索我设计成一场**招聘**，两轮。
>
> 第一轮**海选**：两套方法并行。BM25 关键词检索——按字精确匹配，稳但不懂意思；向量检索——懂意思但抓不住精确术语。两套结果融合，**既懂意思、又认关键词**。快，但粗。
>
> 第二轮**面试**：重排模型把「问题 + 每段候选文献」逐条精读、重新打分排序，只留最相关的进回答。粗筛加快筛，就是业界说的两阶段检索。
>
> 还有个技巧叫 **HyDE**：用户问法常与文献写法不一致——你问「血橙为什么是红的」，文献写的是「花青苷积累」。系统先让模型写一段**假设答案**，再拿它去检索，命中率显著提升。
>
> 最后是筛选标准：不用一刀切固定线，而是**动态阈值**——以本轮最高分 × 0.6 为线，同时设 0.25 的绝对底线，取两者较大值。每次检索的分数分布都写进日志，**后续用统计分布更新底线**，让筛选随语料自适应。

## 第 12 页｜工具系统：给 Agent 配齐手脚

- **页面内容**：书第 4 章：工具分类（感知 / 执行 / 协作）、设计原则（描述、参数保真、粒度）；我的做法：**工具注册表**（分类 / 只读 / 并发键）；四类工具——检索（本地 RAG + 学术库）、读文件（PDF/MD/CSV）、写文件、数据分析；**沙箱**（写仅限 `workspace/output`，读限项目内，严格路径校验）；**权限三档**（auto_workspace / ask 审批卡片 90 秒 / deny）
- **视觉建议**：左半工具箱四格（🔍 📖 ✍️ 📊）；右半审批卡片弹出窗示意：「⚠️ 请求写入文件 output/report.md —— 允许本次 / 拒绝 / 总是允许」
- **讲稿**（约 280 字）：

> 第六个零件：工具。没有工具的 Agent 只能说不做。系统配了四样设备：**检索**（本地库 + 学术库）、**读文件**（PDF/MD/CSV）、**写文件**、**分析**（统计检验）。每个工具在注册表里有「档案」：干什么的、是否只读、能否并发——相当于公司设备台账。

> 工具是把双刃剑：能写文件，也可能写坏文件。安全设计三层：第一**沙箱**——写文件只允许进 `workspace/output` 工作区，读文件限项目目录内，路径逐级严格校验；第二**权限分级**——默认写工作区免询问，危险操作弹**审批卡片**，等你点「允许」才继续，90 秒没回应自动放弃；第三 **deny 模式**——高危操作一律拒绝。
>
> 工具描述也花了功夫打磨——书里强调「工具描述的艺术」，让模型知道什么时候该用哪个。

## 第 14 页｜子代理协作：主管 + 专员，证据全文共享

- **页面内容**：书第 10 章 / §2.7.7：多 Agent 何时优于单 Agent；管理者模式；失败模式；我的做法：**Supervisor 主管 + 三个专员**（检索 / 写作 / 分析），专员上下文隔离、只回传结构化报告；**关键差异：证据全文共享而非摘要**——与编码智能体（OpenCode 等）「隔离 + 压缩传摘要」的做法不同，科研场景每个 chunk 都是证据，数字与机制细节只在原文里，故检索专员回传**证据全文**（上限 4 万字符，单条 ≤2000 字符零截断）进入共享上下文；**追问时经「历史检索证据账本」把上一轮 chunk 全文注入下一轮，无需重新检索**
- **视觉建议**：中间主管 + 三个专员；右侧对比表：编码智能体（隔离 + 摘要压缩）vs 本系统（隔离分工 + 证据全文共享 + 账本复用）；下方画「上一轮证据 → 账本 → 下一轮」箭头
- **讲稿**（约 330 字）：

> 第七个零件，最能体现框架设计：**多 Agent 协作**。为什么不把所有事交给一个大模型？因为一个模型同时干检索、分析、写作，上下文互相污染——原始材料会把写作思路带偏。
>
> 我用**管理者模式**：主管负责听懂需求、派活、汇总；三个专员各管一摊——检索、写作、分析。专员之间**分工隔离**：检索专员看文献，写作专员拿到的是整理好的证据报告，而不是几十万字的原始材料。
>
> 但这里有一个我们和通用编码 Agent（比如 OpenCode）**本质不同的设计**。编码类 Agent 常见的做法是：子任务上下文隔离后，把结果**压成摘要**传回，因为代码片段可以浓缩。但我们做文献检索，**每一个 chunk 都可能是证据**——结论、数值、机制细节往往只在原文里，摘要一压就丢。所以我们的检索专员回传的是**证据全文**，进入共享上下文，回答与写作直接引用原文。
>
> 追问时更省：上一轮的证据会写进「**历史检索证据账本**」，下一轮问题到达时**全额注入上下文**——你想接着问，它不用重新检索一遍，直接基于已有证据回答，既快又避免了上下文重复与重复检索。
>
> 这就是我们面向科研问答这个垂类做的工程取舍：**摘要省 token，全文保证据**，科研场景选全文。

## 第 15 页｜综述写作流水线：从大纲到成稿

- **页面内容**：书 §4.8.2：渐进式披露；我的做法流水线：任务分类（新稿 / 改稿）→ 材料打包 → 生成大纲（展示「📋 执行计划」）→ 大纲校验（章节完整性 + 引用配对，不过重试）→ 3 章并行撰写 → 引用统一编号 → 完整性校验 → 草稿原子发布（`.draft.md` → 校验通过一次性改名，中断不留半成品）→ 断点续传；技能库按章节类型组织（摘要 / 引言 / 方法 / 结果 / 讨论），大纲声明用到哪个才注入全文
- **视觉建议**：8 节点流水线图；大纲节点画「📋 执行计划」折叠块；末尾文件图标 `output/xxx.md`；比喻「开餐厅：先定菜单 → 三个厨师并行做菜 → 上桌前统一摆盘」
- **讲稿**（约 300 字）：

> 所有能力汇成一个杀手级功能：**自动写文献综述**。用「开餐厅」比喻讲这条流水线。
>
> 你说「写一篇黄龙病防治综述」。系统先**定菜单**——生成大纲：标题、摘要、引言、章节、结论、参考文献，直接展示在界面，你一眼知道它打算怎么写。
>
> 然后**采购**——检索专员把文献搜全，按章节分好材料。
>
> 接着**三个厨师并行做菜**——章节分给多个写作任务同时写，比串行快近三倍。这里用上书里「**渐进式披露**」：我有一个按章节类型组织的写作技能库（摘要、引言、讨论等各有模板），但第一步只给模型看技能**目录**，它声明用哪个，写那一章才注入对应全文——**按需查阅，不一次性全塞**。

> 最后**统一摆盘**——重编引用编号、校验每条引用对上文献，然后**原子发布**：先写临时草稿，全部检查通过后一次性改名落盘。哪怕中途断电，也不会留下半成品；重跑还能断点续传。
>
> 用户说「把第三章改一下」，它能精准定位重写。

### A2. 论文候选创新点全景清单（项目盘点 30 条，分四档）

> ✅ = 已有代码/日志/测试支撑（写进论文系统设计章节即可）；🧪 = 需实验数据支撑（对应 A3 实验）。

**第一档 · 场景级创新（科研垂类差异，主打创新点）**

1. ✅ **证据全文共享 vs 编码 Agent 摘要压缩**：通用编码 Agent（OpenCode 等）习惯「隔离 + 压缩传摘要」；科研文献场景每个 chunk 都可能是证据，结论/数值/机制细节只在原文里——故检索专员回传证据全文（cap 40000、chunk ≤2000 字符零截断）进入共享上下文。论证「摘要省 token、全文保证据」的垂类取舍；
2. ✅ **历史证据账本（追问免重检）**：session_evidence 按会话持久化，下一轮以「[历史检索证据]」块全额注入（limit=2 轮），追问不重新检索；DOI+chunk_id 保留可回查原文——避免上下文重复与重复检索；
3. ✅ **确定性证据回执**：回执由代码组装（编号+标题+DOI+证据全文）而非模型自述——「管道而非漏斗」；v8.4.6 前模型自报 34~176 字极短回执导致证据丢失的对照记录；
4. ✅ **动态检索阈值 + 统计自适应**：`阈值 = max(0.25 地板, top×0.6)`，分数分布写检索日志，后续按统计分布更新地板——「固定阈值」到「数据驱动阈值」的演进路径；
5. ✅ **输出画像（确定性篇幅约束）**：由证据量确定性给出篇幅/覆盖**下限**（≥8→1200~2000 字覆盖 ≥6 条等），只设下限不设上限——防「41 篇文献只换 2400 字」的证据浪费。

**第二档 · 工程方法论（可靠性设计模式，可提炼为可复用方法）**

6. ✅ **10 条工程不变量 INV-01~10**：协议配对/生命周期有界/检索降级/上下文传播/输出路由/可观测回归/状态显式化/熔断与输入隔离/证据账本/存储全量·发送裁剪——每条对应一个真实事故与回归测试，可提炼为「Agent 系统可靠性设计模式」；
7. ✅ **症状→根因→修复档案（F1~F9）**：故障驱动开发的完整记录（如 F3 预算截断致 OpenAI 400、F4 模型数不清检索轮次、F7 计时器事件风暴），论文「可靠性工程」章节的现成案例库；
8. ✅ **分级上下文压缩**：软 75%/硬 93% 阈值、保护名单（最近 3 轮/被引证据/DOI）、checkpoint 增量摘要防摘要套摘要、压缩用 FAST 模型、连续失败 3 次熔断降级规则式、截断透明标记 [TRUNCATED]；
9. ✅ **静态前缀 + KV/Prompt 缓存友好设计**：SystemMessage 字节级稳定、动态块一律追加当前轮尾部、cache_metrics 命中率观测（实测 cache_hit 768→65536→68864 tokens）；
10. ✅ **Agent 状态栏（INV-07）**：轮次/工具预算/去重文献数由代码注入 `<agent_status>`，禁止模型自数——「状态显式化」模式；
11. ✅ **存储全量 · 发送裁剪（INV-10）**：messages 表 append-only 为真相源，发送视图可压缩但只压可再生中间过程，核心证据与被引结论保护；
