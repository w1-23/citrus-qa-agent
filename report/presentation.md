# 为什么需要它：科研人的三座大山

<!-- visual: pillar -->

- **文献太多**：柑橘领域公开论文数以万计，示例语料 11.9 万条片段
- **搜索引擎不够用**：给链接不给答案，阅读、总结仍靠自己
- **通用 AI 会「幻觉」**：编造文献名、数据、结论 —— 科研不可接受

> 我们需要 —— 只信真文献 · 每句可溯源 · 能自动成稿

# 上下文工程（一）：静态前缀与 KV 缓存

<!-- layout: two-col -->
<!-- visual: blocks -->

- 上下文 = AI 的「眼睛」：每次回答前打包全部所需信息 —— 长 = 贵
- **KV 缓存**：相同前缀免重复计算，模型「背下」固定内容
- **静态前缀**：系统提示词**字节级稳定** → 稳定命中 DeepSeek 上下文缓存
- **动态内容**：格式指南、技能一律**追加当前轮尾部**，绝不插到前面
- 1,000,000 token 窗口预算 + 右上角实时用量环

---

# 上下文工程（二）：分级压缩与状态栏

<!-- layout: two-col -->
<!-- visual: statusbar -->

- **软阈值 75%**：批量压缩至 50%（缓存只破坏一次）
- **硬阈值 93%**：强制收尾，不再开新任务
- **保护名单**：最近 3 轮问答 / 被引证据全文 / DOI 编号 —— 绝不压缩
- **checkpoint 增量**：只摘要新增部分，防「摘要套摘要」
- **状态栏**：轮次 / 工具预算 / 去重文献数由**代码注入** —— 不让模型自数（实测数错）

# 记忆机制（一）：便利贴 + 长期笔记本

<!-- layout: two-col -->
<!-- visual: sticky -->

- **常驻卡片**（便利贴）：高置信度 ≥0.8 的短事实，≤8 张、每张 ≤500 字，代码自动淘汰
- **长期事实库 LTM**（工作日志）：ADD-only 只追加不覆盖；置信度 <0.5 拒绝写入
- **召回**：语义相似度 × 时间衰减 排序取 top 5
- 记忆提取在后台线程，不与回答抢时间

---

# 记忆机制（二）：偏好、域隔离与隐私

<!-- layout: two-col -->
<!-- visual: drawers -->

- **偏好两层**：全局跨会话（「综述用中文」新会话也生效）+ 会话级覆盖
- **记忆域化**：本会话优先；置信度 ≥0.9 的事实才全局共享
- **日志脱敏**：邮箱 / 手机号 / 身份证 / API Key 自动打码
- **Key 本地化**：state/api_key，权限 600，仅本账户可读

# RAG 知识库（一）：把文献变成「语义图书馆」

<!-- layout: two-col -->
<!-- visual: funnel -->

- **分块 Chunking**：整篇太贵太长 → 切成几百字片段，共 **11.9 万条**
- **稠密嵌入**：文字 → 向量，**意思相近则数字相近**（多语言模型，中英通吃）
- **LanceDB**：嵌入式向量库 —— 百万级 / 热更新 / 免部署
- **一键导入**：自己的 PDF / txt / md → 自动分块 → 向量化 → 入库

---

# RAG 知识库（二）：两阶段检索与动态阈值

<!-- layout: two-col -->
<!-- visual: threshold -->

- **海选**：BM25 关键词（精确）+ 向量（语义）并行，RRF 融合 —— 又懂意思又认关键词
- **面试**：交叉编码重排（bge-reranker-v2-m3）逐条精读重排
- **HyDE**：先写一段假设答案再检索 —— 弥合「问法」与「文献写法」的差异
- **动态阈值**：`max(0.25 地板, 本轮最高分 × 0.6)`；分数分布写日志 → **统计自适应**

# 工具护栏：预算、熔断与停止

<!-- layout: two-col -->
<!-- visual: gauge -->

- **检索预算**：每轮 rag≤2 / academic≤1，请求级 rag≤6 —— 超限代码拦截 + 占位说明
- **收敛判断**：累计 ≥6 篇且本轮新增 <25% → 提前收尾
- **熔断**：连续 3 次工具失败 → 强制收尾，不无限重试
- **停止按钮**：一键取消 —— 用户永远保留控制权

> 四道护栏全部是**代码写死的硬约束**，不靠提示词劝模型「自觉省钱」

# 子代理协作：主管 + 专员，证据全文共享

<!-- visual: team -->

- **主管 Supervisor**：理解需求 / 派活 / 汇总；轮次与预算由代码裁决
- **三个专员**：检索 / 写作 / 分析 —— 分工隔离，只回传结构化报告
- **与编码 Agent（OpenCode 等）的本质差异**：
  - 编码类：隔离 + 压缩传**摘要**（代码片段可浓缩）
  - 我们：**证据全文共享** —— 结论 / 数值 / 机制细节只在原文，摘要一压就丢
- **历史证据账本**：追问时全额注入上一轮证据 → **免重新检索**

- 定向修改：「把第三章改一下」精准定位重写

# 完整例子串讲：一次提问走完全程

<!-- visual: timeline -->

用户：**「写一篇柑橘黄龙病防治的文献综述，保存到工作区」**

1. **接单**：恢复会话历史 + 召回长期记忆（偏好中文）
2. **派活**：路由表判定「撰写新内容」→ 派检索专员 + 写作专员
3. **找材料**：HyDE → 混合检索 → 重排 → 动态阈值 → 预算内收敛 → 证据全文报告 + 账本
4. **写作**：出大纲 → 3 章并行 → 技能按需注入 → 引用编号
5. **交稿**：完整性校验 → 原子落盘 workspace/output → 「工作区」可见
6. **评价**：👍 + 评论入库 → 成为改进养料

> 追问场景：账本注入上轮证据全文 → 免重新检索
