# 🍊 CitrusQA · 确定性优先垂类智能体

**面向柑橘研究的中文可问、引用可核、时效有界的检索增强问答系统。**
提问以中文为主、可引用的文献以英文为主；答案必须能点开 DOI 或官方 URL 逐条核对。

> 本仓库只承载**代码脚本**（系统源码 + 配置 + 前端 + 部署脚本）；测试与各类杂项不在公开集内。
> **语料不进仓库**（单文件最大 247 MB，超出 GitHub 限制），由 [`Releases`](https://github.com/w1-23/citrus-qa-agent/releases) 分卷分发，`run.ps1` 首次运行自动下载。

---

## 一、它解决什么

通用大模型与常规 RAG 在这类场景有三类**可复现**的问题，每类都有量化观察：

| 问题 | 实测 |
|---|---|
| **跨语言词面召回失效** | 中文问句在英文语料上的 BM25 通道命中率 **0.0%（0/48）**；忠实英译后 **97.9%（94/96）** |
| **联网证据污染本地引用** | 未过滤的联网片段混入本地证据池，模型侧幻觉率 **3.1% → 24.0%**（+20.8 pp，超过该比较的 MDD）；仅在模型可见级做相关性过滤仍为 18.8% |
| **直接作答存在溯源幻觉** | 正文编号与真实来源并不逐条对应 |

CitrusQA 的对策是**把语义判断交给模型、把确定性约束交给代码**。

## 二、核心结论：可用性支配精制

在垂直语料中，真正的约束是**进入生成器窗口内容的信噪比**，而不是排序的精美程度。
五组受控机制实验，一次只改变一个因素，题目全部锚定在已知金标片段上：

1. **提问语言是整条管线的主导因素** —— 中文直检 BM25 命中 **0/48**；忠实英译 **94/96**（47/48 个金标片段）；在中文问题中嵌入英文术语锚点可重建跨语言词法桥，从 0/48 恢复到 **36/48**。
2. **精排与呈现顺序是准入阀，不是质量放大器** —— 它们可测地改变证据窗口的客观构成，但全部两两比较**测不出判分差异**；真正起作用的是金标片段是否进窗，差距约 **1.6–2.0 判分点**。
3. **查询扩展是一场零和上下文博弈** —— 八种扩展配方无一胜过原始单路查询；每种配方新增捞回的金标片段都为 **0**，同时挤出 **1–31** 条（窗口挤出效应，而非证据创造）。
4. **把金标片段移出证据窗口损失 −0.45 判分点**，换成等长随机片段损失相同；预算减半时以乱序而非排序交付窗口，会使金标可用性**减半**。
5. **对实时联网证据，架构隔离胜于算法过滤** —— 三种逐级加严的过滤停在 18.8%–33.3%，准入分数几乎不带信号（**AUC ≈ 0.58**）；可辩护的边界是**引用池的物理隔离**。

> **边界**：上述结论成立于一条固定管线、一个以英文为主的柑橘语料与一种切块方案。
> 跨语言结果是对英文语料的**通道级测量**，不应读成"中文检索处处失效"。

## 三、系统架构（执行流程五层解耦）

```
入口与改写  →  监督者统一决策  →  双智能体并发  →  装配与代码校验  →  两段式分离输出
```

- **入口与改写**：浅问挡板 · 人工介入（HITL）意图确认 · 中文→英文忠实改写
- **双智能体并发**：本地文献检索智能体（掌握证据池并生成答案：向量 + 词面双通道 → RRF(k=60) → bge-reranker-v2-m3 精排 → 动态阈值准入）与联网信息获取智能体（只取回时效原文，检索轮次受上限约束）
- **证据隔离（代码级）**：两类来源在检索入口、存储位置与可采纳性判定上被分开；联网内容只作**第二段分离输出**，不进本地引用池、不占编号
- **引用校验**：交付层代码校验越界引用；第一段以本地文献库标题起头、逐条对应 DOI 可供跳转，第二段单列联网内容并标注"未经本地证据验证"

**检索配方**：`top_k_vector=40 · top_k_bm25=40 · rrf_k=60 · candidate_window=20`，
动态阈值 `T = max(0.25, s_top × 0.60)`，早停「证据 ≥6 且本轮新增比 <0.25」。

## 四、评测纪律

- **十维量表（ARE）** 盲评；**两位独立判官 `kimi-k2.6` + `glm-5.3`，从不合并平均**，一律逐判官报告。
- **逐判官最小可测差**：`MDD = t_{.975, n−1} · SD(逐题配对差) / √n`。
  配对差越过该判官自己的 MDD 才写"更好/更差"，否则正式结论为"**不可分辨**"——"不可分辨"不等于"无效应"。

**关键读数**：

| 项 | kimi-k2.6 | glm-5.3 |
|---|---|---|
| 真实用户提问 132 题 · ARE 十维均分 | **4.3622** | **4.3942** |
| 相对 Track B（同基座·不检索·共享提示词与校验） | +0.0173（MDD 0.1643）**不可分辨** | +0.6372（MDD 0.1596）**可分辨** |
| 系统层 84 题批引用核查 | 正文 **1,649** 个引用标记、**越界 0 个**，平均每题被引证据 2.58 条 | 同 |

> 两位判官灵敏度不同不是矛盾，而是**仪器差异**：同一条差异可能 glm 看得出来、kimi 看不出来。

## 五、部署

```powershell
# 1. 取得框架
git clone https://github.com/w1-23/citrus-qa-agent.git
cd citrus-qa-agent

# 2. 一键启动（自动：语料下载 → Python 检测 → 虚拟环境 → 依赖安装 → 模型下载 → 起服务）
powershell -ExecutionPolicy Bypass -File .\run.ps1

# 3. 浏览器自动打开 http://localhost:8000 —— 首次在页面内填写 API Key（仅存本机）
```

也可从 [`Releases`](https://github.com/w1-23/citrus-qa-agent/releases) 下载主包 zip，解压后双击 `run.ps1`。

**语料分卷**（挂 v9.4.0 Release，`run.ps1` 自动按序下载解压到 `agent/data`）：

| 附件 | 大小 | 内容 |
|---|---|---|
| `corpus-v9.4.0-1.zip` | 1002 MB | 语料分卷 1/5 |
| `corpus-v9.4.0-2.zip` | 591 MB | 语料分卷 2/5 |
| `corpus-v9.4.0-3.zip` | 2.2 MB | 增量分卷 3/5：`CGI_experiment_methods_english` |
| `corpus-v9.4.0-4.zip` | 2.3 MB | 增量分卷 4/5：`Chinese_Citrus_Varieties_Deng_Xiuxin` |
